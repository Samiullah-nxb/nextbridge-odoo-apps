Multi-Database MCP Server – AI Connector for Odoo

Give AI assistants a safe, audited way into Odoo. One connector address reaches this database, other databases on the same server and databases on other Odoo servers.

Odoo 18 Model Context Protocol (Streamable HTTP) 109 tools in 11 switchable packs Connector keys + OAuth 2.1 sign-in

One assistant, all your databases

Companies often run several Odoo databases: one per country, per branch or per brand. Register them once and the assistant can work in any of them, or compare them in a single question.

This database

Every tool pack, using the signed-in user's own access rights.

Other databases on this server

Opened directly, authenticated with an Odoo API key of that database. All packs when the app is installed there; data tools otherwise.

Databases on other servers

Data tools over Odoo's external API, or every pack when the remote server runs this app too (calls are forwarded to its own connector).

The assistant sees a database choice on every tool, plus hub_search_all to run the same search or count in every database at once ("How many open opportunities does each branch have?").

Packs are switched on and off on one screen. Every tool switched on is described to the assistant in every request, so switching off what you do not use also makes answers faster and cheaper; the screen shows the estimate.

Dashboards built from a sentence

"Make me a sales dashboard: revenue, open pipeline, revenue per salesperson and orders per month." The assistant builds it, checks the figures and sends a link. Every viewer only sees figures for records they are allowed to access.

Built for safety

  • Odoo's own rights apply. The assistant acts as a real user: access rights, record rules and multi-company stay in force.
  • Connector keys are stored as hashes, can be read-only, limited to some databases, given an expiry date and revoked.
  • OAuth 2.1 sign-in (PKCE, dynamic client registration, rotating refresh tokens) for apps that cannot store a key.
  • Read-only switch for the whole company, a separate switch for deleting, and confirmation for anything irreversible.
  • Activity log of every call: who, which tool, which database, duration, result; secrets are masked.
  • Limits: maximum records per answer and calls per minute per key.
  • Website changes need an explicit permission per website and page, and every content change can be undone.
  • Restrictions never apply to administrators and administrator rights can never be granted by the assistant.

Connect in three steps

  1. Install the app and open AI Connector → Connect → New connector key.
  2. Add the connector address to your AI app as a remote MCP server. Apps with header support send the key as Authorization: Bearer <key>; desktop apps get a ready-made JSON configuration; apps with a sign-in flow open an Odoo consent page instead.
  3. Ask in plain language: "Compare this month's sales of all our companies", "Create a dashboard of overdue invoices", "Hide the Invoicing app from the warehouse team".

Questions

Which AI apps work with it?
Apps that support remote MCP servers over Streamable HTTP, either with a header (connector key) or with OAuth sign-in. Desktop apps that only start local servers can use the generated mcp-remote configuration.

Do I need a special Odoo setup?
No for one database per domain. On a server that hosts several databases without a database filter, add the app to server_wide_modules so each database is reachable at /mcp/db/<name>; the settings page explains it.

Does it change Odoo's core?
No. It depends only on base and web; CRM, Email Marketing and Website tools switch on when those apps are installed.

Does the AI provider see my data?
Only the answers to the tools the assistant calls, within the user's rights and the packs you allow. Keep sensitive packs off and use read-only keys where possible.

Is it tested?
The app ships with an automated test suite (protocol, data tools, dashboards, CRM, email campaigns, access control, website, HTTP endpoint and the full OAuth flow).
